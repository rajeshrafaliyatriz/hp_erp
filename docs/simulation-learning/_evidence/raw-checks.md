Saved 2026-10-26 from the approved plan (the whole plan is in `_evidence/approved-plan-2026-10-26.md`). Claims are tagged verified, inferred or unverified in the source text.

**A4. Download sizes I measured from jsDelivr (npm latest, gzip -9).** three 0.186.1 core 190 KB (raw 790 KB), three WebGPU build 400 KB; Babylon.js 9.32.0 monolithic bundle 1,842 KB (raw 8.5 MB; the tree-shaken `@babylonjs/core` is smaller); PlayCanvas 2.23.3 640 KB; A-Frame 1.8.0 (includes three) 341 KB; Google model-viewer 4.4.0 282 KB; Rapier physics WASM 1,141 KB (raw 3.0 MB); Havok WASM 643 KB (raw 2.0 MB). A physics engine therefore costs more to download than the 3D library itself.

**A8. A live comparable site, torn down with the Step 0 method (8gwifi.org/biology/cell-atlas.jsp, page source read 26 Oct 2026).** A working 3D cell atlas with 12 cell types, organelle highlight, focus mode with a slicing-plane cross-section, and side-by-side comparison (the same features as the Cell Architecture Studio video). Stack: plain three.js 0.160.0 from an import map, OrbitControls, no framework. Nine cells are built in code from primitives; three (animal, neuron, bacteria) load real NIH 3D Print Exchange GLB models, which the page itself says are "used under their CC BY-NC-SA 4.0 license" (non-commercial, so unusable in a commercial product such as G2G). Model files total 4 to 5 MB. Its own code is small: the scene script is 93 KB and the cell data 108 KB (48 KB gzip together), with GLTFLoader, OrbitControls and three.js clipping planes for the cross-section, which is a built-in three.js feature. Lesson: a polished cell explorer is within reach of plain three.js, and "real 3D models" from public libraries can carry non-commercial terms.

**A9. Teardown of the live Learn Arduino app (learn-arduino-red.vercel.app, 26 Oct 2026).** A Vite build with three files: a 6 KB bootstrap (a 13-language i18n loader: en, es, pt, fr, de, it, tr, id, zh, ja, ko, hi, he with right-to-left support), a 129 KB main chunk (44 KB gzip) holding all lesson data (16 lessons whose ids are blink, builtin, button, force, heat, knob, light, motor, piano, plant, project, rgb, sensor, servo, sound, stepper; fields `pinout`, `features`, `code`), and a 415 KB stage chunk (108 KB gzip) with a tree-shaken three.js: WebGLRenderer, PBR (MeshStandardMaterial) and toon materials, directional, point, spot and hemisphere lights, shadow maps, orthographic and perspective cameras, canvas-texture text labels. Absent: any glTF, OBJ or texture loader, any .glb reference or embedded model, avr8js or any emulator, WebAssembly, post-processing, any network call, any AI call. The method that runs a sketch prints "Compiling sketch…", waits 600 ms, prints "Uploading to Arduino Uno…", waits 600 ms, prints "Done uploading." (skippable through an `instantRun` flag) and then starts a hand-written simulator (`ms(...)`) bound to the scene's pins, parts and LEDs; the code panel highlights tweakable constants (screenshot 6 shows 24 and 1200 highlighted). There is a reduced-motion switch (`setReducedMotion` slows tweens to 0.05) and a grid toggle. Conclusion: the most admired "3D Arduino lab" is procedural 3D with a scripted simulator, about 155 KB of JavaScript in total, so visual polish here does not depend on authored or AI-generated meshes. The code panel is a parametric editor, not arbitrary code execution, which is also the safe design for the runtime.
