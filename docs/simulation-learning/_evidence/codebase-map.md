# Codebase map (corporate LMS and K-12 repos)

Saved 2026-10-26 from the approved plan (the whole plan is in `_evidence/approved-plan-2026-10-26.md`). Claims are tagged verified, inferred or unverified in the source text.

## What the two codebase maps found (read-only, 26 Oct 2026)

**Corporate LMS (`hp_erp` Laravel + `g2gv0` Next.js).**
- A lesson is a row in `content_master` (course = `sub_std_map`, module = `chapter_master`). The lesson type is free text (`file_type`), never whitelisted. The front end keeps four hard-coded copies of the type list (`services/lms/course-builder.ts:97`, `create-course-page.tsx:74-81`, `course-authoring.tsx:41-51`, `learning-delivery-workspace.tsx` 80-99 and 364-479). A `simulation` type therefore needs those four edits, a manifest table (raw DDL, LONGTEXT) and a package upload path (the `mimes:` whitelist at `LmsLearningController.php:1262` excludes zip, html and wasm).
- The only iframe precedent is `InteractiveCourseLauncher` (`learning-delivery-workspace.tsx` 262-362): link lessons on the Spaces host whose URL ends `/interactive/_player/course.html`. The iframe has no `sandbox` attribute; messages are `{src:'g2g-course', type:'progress'|'completed'}`; the host checks origin and lesson id but not `event.source` and never replies. The player page itself is not in either repo.
- Progress goes to `POST /api/lms/learning/progress` (`saveProgress`, `LmsLearningController.php:608-761`): status, position and time only. It accepts no score or attempt data, is select-then-write (not atomic) and trusts the client's "completed". The `course.completed` event is effectively never emitted from the learner UI; certificates are minted in two places with two numbering schemes (`CERT-…` and `G2G-…`).
- Events: `g2g_event` has UNIQUE(sub_institute_id, idempotency_key); `EventRecorder::record` is a plain insert, so a repeat throws and the caller must catch it. No xAPI, cmi5 or LTI code exists; SCORM is a placeholder; H5P is an empty stub.
- Assets: DigitalOcean Spaces bucket `s3-triz` (fra1), upload is admin/HR only, 100 MB, public path `public/lms_content/<tenant>/…`. Neither repo sets any CSP or frame header. The login token sits in browser localStorage, so generated or third-party code must run on a different origin.
- Tenancy: LMS routes carry no route middleware; controllers guard themselves (`ResolvesLmsIdentity`) with manual `where sub_institute_id`. Two existing gaps a new feature must not copy: the `saveProgress` ownership check has no tenant filter, and `course()` does not require enrolment.
- Migrations: raw `CREATE TABLE`, LONGTEXT not JSON, VARCHAR plus a PHP constant not ENUM, no foreign keys, short index names (max 767 bytes), `ColumnExists` helper; run per file on the default DB and with `--database=live`. The newest migration is dated 2026_12_02, so new files must sort after it. Menu-row template: `2026_10_14_100400_create_capability_gap_inbox_menu_row.php`.
- AI: DeepSeek (`deepseek-flash`, $1 balance floor) powers the course outline; the Vercel AI SDK is used only for Gemini in `g2gv0`. Per-tenant AI quota is enforced only on the `AiModelClient` path; the DeepSeek path only records. A simulation AI gateway therefore needs its own enforced per-tenant quota.
- Build: `typecheck` is the real gate (`ignoreBuildErrors: true`); tests are `node:test` (34 files, none for components); no Playwright, Vitest, three, R3F, XState, Monaco, CodeMirror, workers or WASM; lazy loading is `React.lazy` only.
- Docs convention: `Docs\<feature>\00-PROGRESS.md` ("read first in a new session") + `DECISIONS.md` (+ `PLAN.md`, `_evidence\`). No RESUME.md, STATE.md, ADR folder or CLAUDE.md exists.

**K-12 repos (`lms_k12`, `next_lms_erp`, `D:\g2g-step2-work`), owner-built, all 2D.**
- No three.js, R3F, matter, p5, PhET, GeoGebra, WebGL or .glb anywhere. No LICENSE file, and commits come from several GitHub identities under two remotes: confirm contributor IP assignment before relying on any of it.
- Study Deck: 8 unscored interaction kinds (hotspots, scenario, reveal, steps, timeline, compare, match, order) on DOM + inline SVG. Its harness posts `{src:'studydeck', event:'progress'|'finished'}` to a wildcard origin; no score; nothing stored server-side.
- "H5P": there is no H5P runtime. It is 15 native React re-implementations (2D) plus 10 planned. Their xAPI statements post to `/api/pal/h5p/xapi` (the only xAPI pipeline in the estate). Only 5 of 11 exports import into Lumi.
- Prayogshala: a JSON `lab_config` + 6 engines (calculator, relevance, osmosis, variable_model, sequence, classify) + a safe formula parser + a validator + an AI generator, with an 8-step flow (mission, predict, do, observe, explain, concept, apply, reflect), 19 SVG visuals, 10 authored labs (none physics or chemistry); results are not saved.
- Verdict: none of this is a 3D engine or a high-end visual runtime, so it cannot be the foundation for the quality you want. What is worth keeping is the pattern (data-driven config + validator + AI generator + predict-observe-explain flow), which the new runtime should generalise only if it wins on merit.
