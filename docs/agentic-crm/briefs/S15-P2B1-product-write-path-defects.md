## The defects (file:line as read by the caller on 13 Nov; lines move, re-read)
**D1. A product line is created before the right to add is checked, and by anyone.** `app/Http/Controllers/Api/Crm/CrmProductController.php` `store()`: `resolveOrCreateProductLine()` runs at about :206, the add-right check `canOnType($identity, $itemType, 'add')` only at about :215, and the tax-rate check between them. A person with no add right can therefore create a `g2g_product_master` product row and a `g2g_signal_products` row. Also `resolveOrCreateProductLine` (:892-947) lets any person with the add right create a NEW line, while `ProductWriter::createProduct` (S1) allows that only for an administrator. `update()` has the same inline creation (:289-291).
 Wanted: order is validate, then right to add or edit, then tax rate, then line resolution, then write. An EXISTING line named in the request (case-insensitive name, the tenant's or shared) may be used by anyone with the right. A NEW line needs what `ProductWriter::createProduct` needs (read `ProductAccess`; same rule, same refusal wording style, HTTP 403) and when refused NOTHING is written (assert the row counts of `g2g_product_master`, `g2g_signal_products` and `crm_products` are unchanged). Line creation must go through ONE method shared with the writer (move the logic out of the controller into the ProductMaster domain, for example next to `ProductWriter`), not a second private copy.
**D2. The line key does not fit its column and skips the rules.** The private method writes `product_key` up to 50 characters into `g2g_signal_products.key`, which is `varchar(20)`, and ignores `CustomProductRules` (reserved words, slug shape). Strict MariaDB would error half way, non-strict silently truncates (and a truncated key can collide). Wanted: the key obeys `CustomProductRules` (read it: length 20, reserved list including the new reserved word `products` that the route `/portfolio/products/{id}` will need: add it to `RESERVED`), a clash gets a short deterministic suffix that still fits 20, and the master row and the signal-product row carry the SAME key.
**D3. Services lose their line.** `store()` (:238-240) and `update()` (:323-325) force `product_master_id` to NULL for every service, so any edit evicts a service from its line (dev data: two services under the ScholarClone line carry `product_master_id` 1 from the seeder and would lose it on the next edit). Wanted: a service is treated like a product here: `productMasterId` is stored when sent (and visible, kind `product`), and an update that does not send it leaves the stored value alone.
**D4. History has no right check and shows cost and commission.** `routes/api.php` `products/{id}/history` has no middleware; `app/Http/Controllers/Api/Crm/Concerns/HasCrmAuditTrail.php::history` checks the tenant only; the diffs carry `cost_price` and `commission_rate`. Wanted: only a person who may VIEW that item type (`canOnType($identity, $row->item_type, 'view')`, the same right the list uses) reads its history; otherwise 403. Do this through a small hook on the trait that other controllers do not override (their behaviour must not change: prove it with the existing tests of one other controller that uses the trait).
**D5. A line id is not checked on import and in the writer.** `import()` (about :772) and `ProductWriter::createItem` (about :181, `parentId`) store a line id without `LeadLinks::productVisible`. Wanted: both reject an id that is not a visible Product (kind `product`, the tenant's or shared; a Sub-product id is not a Product); in `import` a bad row is reported as a row error in the same shape the importer already uses, the other rows still import.
