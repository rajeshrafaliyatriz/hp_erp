## A. Document Library sync (backend, Track D)
Every FILE uploaded to a Product's Sales Kit lands in the Document Library under this folder tree, per organisation:

    Sales Kit                (root folder, parent NULL)
      <Product name>         (one folder per Product, e.g. "ScholarClone")

- Folders are `document_folders` rows: `sub_institute_id` = the tenant, **`owner_id` NULL** (an org-wide folder is owned by nobody: see the table's own comment), `visibility = 'organization'` (every same-tenant user sees them in the library tree), `created_by` = the acting user, `sort_order` 0.
- The uploaded document row gets `folder_id` = the Product's folder (set directly on the row; NOT through the library's folder-upload endpoint, which needs folder ownership). `document_type` stays 'Sales Kit'.
- Find-or-create, inside the same transaction as the upload: the root by (tenant, parent NULL, name 'Sales Kit', not deleted); the product folder FIRST from the `folder_id` of an existing kit document of the same product (a kit row whose document has a folder whose parent is the root), otherwise by (tenant, parent = root, name = product name), otherwise create. If the folder found through an existing document is named differently from the product's current name, rename it (the Product was renamed). Never touch a folder that is not under the Sales Kit root, never create duplicates on a re-run.
- **A document added "From Document Library" is NOT moved** (it already lives in somebody's folder; moving it would surprise its owner). Say so in the report.
- A link item has no document, so nothing is made in the library. Removing a kit item never deletes the library document or its folder (existing rule).
- Tests: first upload creates root + product folder with the right fields; a second upload (same product) reuses them (no duplicates); a second product gets its own folder under the same root; another tenant gets its own tree; a renamed product renames the folder; a folder named "Sales Kit" that is NOT a root (has a parent) or belongs to another tenant is never reused; from-library does not change `folder_id`; the document row, history row, link row and kit row are all still written; the upload still works when the `document_folders` table or the `folder_id` column is absent on a host (skip the folder, still upload; never fail an upload because of the folder). Mutation proofs: always create a new folder; drop the tenant filter in the folder lookup.

### Managing a link (Track D builds, E consumes) - existing `/api/product-master` group, `api.token`
`KitItem` gains `share: null | { token: string, expiresAt: string | null, sharedAt: string, expired: boolean }` (null when not shared; a viewer sees it too: sales staff copy the link to send to a customer; only managers create or stop it).

| route | right | body | answer |
|---|---|---|---|
| `POST /{id}/kit/{itemId}/share` | `edit` | JSON `{ days?: 7 \| 30 \| 90 \| 365 \| 0 }` default 30; 0 = no expiry | 201/200 `data: KitItem` with `share`. Creates a token (`Str::random(48)`, URL-safe) or ROTATES an existing one (the old link stops at once). 422 `not_shareable` for a link item whose `url` starts with `/` and is NOT a known deck path `/signals/portfolio/deck/<key>` (a page inside the app cannot be public); 422 for a file whose library document is missing. |
| `DELETE /{id}/kit/{itemId}/share` | `edit` | | `data: KitItem` with `share: null`. Idempotent. |

Rules: tenant-scoped like every kit route; a soft-deleted kit item has no link (removing an item ends its link); editing the kit item's title/description never changes the token; PATCH `url` on a shared link item to an unshareable internal path clears the share.

### The public side (Track D builds, E consumes). NO authentication, NO session. Registered in `routes/product_master.php` as its own block, prefix `api/public/sales-kit`, middleware `['api', 'throttle:60,1']` (the file route `throttle:30,1`).
- `GET /api/public/sales-kit/{token}` -> `{ status: 1, data: { title, description, kind, source: 'file'|'link', productName, fileName, mimeType, size, url, deck, expiresAt } }`. `url` only for an external `https://` link item (else null); `deck` = the deck key (`scholarclone`, ...) for a link item whose url is `/signals/portfolio/deck/<key>` (else null). No tenant id, no user ids, no document id, no `createdBy`.
- `GET /api/public/sales-kit/{token}/file?inline=1` -> the bytes of a FILE item. `Content-Type` from the row; `X-Content-Type-Options: nosniff`; `Cache-Control: private, no-store`; `Referrer-Policy: no-referrer`; `X-Robots-Tag: noindex, nofollow`; `Content-Disposition: inline` ONLY when `?inline=1` AND the type is pdf, an image (png, jpeg, webp, gif) or a video (mp4, webm, mov); anything else is always `attachment`. 404 for a link item. A download (not inline) writes an audit row to `document_library_history` (`action 'downloaded'`, `details {"via":"sales_kit_public"}`, `created_by` NULL, the ip).
- **Every refusal is the SAME plain 404** `{ status: 0, message: 'This link is not available.' }`: unknown token, a token of the wrong length/charset, stopped (revoked), expired, the item removed, the library document missing or deleted, the table or columns absent. A caller cannot tell which. Look the token up by equality on the unique index (validate `^[A-Za-z0-9]{48}$` first).
- Tests: create/rotate/stop; the public meta and file with the right answers and headers; expired (a past `share_expires_at`) and stopped and removed-item and rotated-old-token all 404 identically (assert identical body and status); malformed token 404 without a DB hit if you can prove it; a link item with an external https url returns `url`, with the deck path returns `deck`, an unshareable internal path is refused at creation; inline only for the safe types (an uploaded .pptx/.docx/.txt is always attachment even with `?inline=1`); no private ids in the JSON (assert the key set exactly); rights: no row => 403 on share/stop, view-only cannot create or stop but SEES an existing `share`; tenant isolation (another tenant's product/item id under a mine => 404); the public routes carry NO `api.token`/auth middleware and DO carry `throttle` (route-map test); 503 `not_set_up` for create/stop on a host without the columns; the audit row on a non-inline download only. **Mutation proofs:** drop the expiry check; let a revoked token still answer; return the document id in the public JSON; allow `inline` for a pptx. Each must fail a test.
