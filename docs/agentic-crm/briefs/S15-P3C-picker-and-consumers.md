## Goal
Every place that lets a person choose a product uses one component, with the owner's words (**Product** for the top level, **Sub-product** for what is sold; never Catalogue, Offer, Item or Product line on a screen you touch), grouped by Product, search-as-you-type, showing SKU and price (price only when the API sends it). Today about 20 ad-hoc pickers call two different endpoints (`GET /crm/products?itemType=` called twice, capped at 100 rows, and `GET /product-master/options`).

## What to build
1. **`components/domain/portfolio/product-picker.tsx`** + `lib/product-picker/*` (pure model, tones) + `services/product-master/picker-service.ts`:
   - `SubProductPicker`: for DOCUMENT LINES (quote, sales order, purchase order, invoice, price-book item, opportunity product, bundle component, ticket, asset, FAQ). Calls `GET /api/product-master/picker?type=&q=&limit=` as the person types (debounced, cancels stale requests), shows `Product › Sub-product`, SKU and (when present) price with currency, returns **`crmProductId`** (the id every line-item table stores) plus the price, currency, tax rate id and name the old pickers handed to their forms. A value already on a document that the picker no longer offers (paused, binned) is still displayed by name (resolve it through `GET /api/product-master/{id}` or `/by-crm/{crmId}`), never shown as blank.
   - `ProductPicker` (level 1): for the leads, campaigns and opportunities forms, which store a Product (`product_master_id`). Calls `GET /api/product-master/lines` (or `/options`, whichever the P2-E1 log says carries the Products), returns the master id; label says **Product**.
   - States: loading, empty ("No sold sub-product matches"), error with Retry, keyboard (listbox roles, arrow keys, Escape), 390 px, axe, tones method (`lib/signals/tones.ts`), a `data-` hook for tests. Reuse `components/ui` pieces without editing them (`SearchableSelect` exists; if it cannot do remote search, wrap it, do not edit it).
2. **Retarget every consumer, one at a time, each with its own test** (list from the audit and the front-end map; search `services/crm/index.ts` for `getProducts`/`itemType` callers to be sure none is missed):
   - document lines: `quote-detail-page.tsx` + `quote-line-item-table.tsx`, `sales-order-detail-page.tsx` + `sales-order-line-item-table.tsx`, `purchase-order-detail-page.tsx` + `purchase-order-line-item-table.tsx`, `invoice-detail-page.tsx` and `create-invoice-modal.tsx`, `price-book-detail-page.tsx`, `opportunity-detail-page.tsx` (Products & Services tab), `create-ticket-modal.tsx`, `create-asset-modal.tsx` (required), `create-faq-modal.tsx`; the quote price logic (price-book price, else `unitPrice`) and tax rate defaulting must stay exactly as they are;
   - Product (level 1) fields: `create-opportunity-modal.tsx` + `opportunity-form-options.ts`, `create-lead-modal.tsx`, `lead-list-view.tsx` facet, `create-campaign-modal.tsx`, `campaign-parts.tsx`.
   Do NOT touch `product-detail-page.tsx`'s bundle dialog (Track P3-B moves it) nor the Products list and Services list (Track P3-A replaces them).
3. **Links to product pages**: every `href` to a product page in the files above and in `components/domain/crm/asset-detail-page.tsx`, `ticket-detail-page.tsx` and others (grep `sales/products` and `resolveAccessLink` call sites listed in the audit) points at `/portfolio/products/{masterId}` (use `GET /by-crm/{id}` data the picker and the document responses already carry, or the `masterId` field of the CRM product resource) instead of `/module/crm/sales/products/...`; the seven call sites that `resolveAccessLink('/module/crm/sales/products')` for a right check keep resolving the SAME menu link (rights stay on rows 468/469), but must not rely on that row being in the sidebar: use a small helper that asks the rights, not the tree, if the tree lacks the row (read how `ticket-detail-page.tsx:259` and `asset-detail-page.tsx:147` use it and fix the fallback to `/dashboard` in those places).
4. **Backend-emitted links**: `ListProductsTool.php` (hp_erp) emits `/module/crm/sales/products/{id}`, `/services/{id}`, `/products/lines/{id}`; the redirects keep them working, so you only REPORT the line numbers (a backend caller changes them), do not edit hp_erp code.
