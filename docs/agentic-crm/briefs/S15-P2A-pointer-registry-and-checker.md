## Goal
Before anyone changes how a product is written, there must be (a) ONE registry of everything that points at a product, (b) a read-only command that proves those pointers still resolve and that the three stores (master row, Portfolio offer, CRM item) agree, and that can compare a before and an after snapshot of the quote, order and invoice lines, and (c) the Portfolio's ICP sync pulled out of the controller so the writer can reuse it. Nothing in this track changes behaviour.

## 2.1 Registry and checker
**Files (new):** `app/Domain/ProductMaster/ProductPointers.php`, `app/Domain/ProductMaster/ProductIntegrity.php`, `app/Console/Commands/ProductMasterCheckCommand.php` (signature `product-master:check {--tenant=} {--database=} {--snapshot=} {--compare=}`). Follow how `product-master:backfill` and `product-master:repair` are built and registered (find them first) and how organisation merge keeps ONE registry with a scan test (`app/Http/Controllers/Api/Crm/Concerns/HasCrmMerge.php`, `tests/Feature/OrganisationMergeTest.php`): reuse that idea.
**Registry (verified on dev 13 Nov, re-verify against the migrations):**
- Point at `crm_products.id` (12 columns in 11 tables): `crm_assets.product_id`, `crm_campaigns.product_id` (loose, no FK), `crm_faqs.product_id`, `crm_invoice_line_items.product_id`, `crm_opportunity_products.product_id`, `crm_price_book_items.product_id`, `crm_product_bundle_items.parent_product_id` and `.component_product_id`, `crm_purchase_order_line_items.product_id`, `crm_quote_line_items.product_id`, `crm_sales_order_line_items.product_id`, `crm_tickets.product_id`.
- Point at `g2g_product_master.id` (10 columns): `crm_campaigns.product_master_id`, `crm_leads.product_master_id`, `crm_opportunities.product_master_id`, `crm_products.product_master_id` (means the PRODUCT, level 1, id: keep that meaning), `g2g_company_opportunities.product_master_id`, `g2g_product_claims.product_master_id`, `g2g_research_runs.product_master_id`, `gtm_campaigns.product_master_id`, `gtm_outreach_messages.product_master_id`, `gtm_playbooks.product_master_id`.
- The master's own pointers: `crm_product_id` to `crm_products.id`, `offer_row_id` to `g2g_product_offers.id`, `parent_id` to a master row of kind `product`.
- **Scan test:** list every table and column in the test schema whose name ends in `product_id` or equals `product_master_id` or contains `crm_product`, and fail if one is neither in the registry nor in a short allowlist that carries a written reason per entry. Register tables lazily: a table that does not exist on a host (older live schema) is skipped, never an error. Use `ColumnExists` / schema helpers, never a bound `SHOW COLUMNS ... LIKE ?`, no JSON functions, no window functions, no CTEs (`tests/Unit/MariaDb101SafetyTest.php` scans `app/Domain/ProductMaster` and will fail your code if it breaks a 10.1 rule).
**Checker invariants (error = non-zero exit; warning = printed only):**
- I1 (error) a registered pointer with a value whose target row does not exist; also count pointers that cross to another tenant.
- I2 (error) a master row whose `crm_product_id`, `offer_row_id` or `parent_id` does not resolve, or whose parent is not kind `product`.
- I3 (error) two live master rows (same tenant) sharing a `crm_product_id` or an `offer_row_id`.
- I4 (error) a live (not binned) `crm_products` row with no master row, or a Portfolio offer row with no master row.
- I5 (error) on a master row that holds both pointers: names differ between master, offer and CRM item; `offers.parent_product` differs from the parent master's `portfolio_name`; `crm_products.product_master_id` differs from the master's `parent_id`. On a row that holds only one pointer the same checks apply to what exists.
- W1 (warning) a live master row pointing at a binned CRM item; W2 a tenant-0 (shared) master row holding a CRM pointer.
**Snapshot / compare:** `--snapshot=<file>` writes a JSON census (per registered pointer table: row count and, where the columns exist, `SUM(quantity)` and the sum of the row's total/amount column; plus, per product id, the number of referencing rows for the line-item tables) and `--compare=<file>` prints every difference between that file and the database now and exits 1 when there is one. The command is READ ONLY: it never writes to any table, and a test proves it (row counts and `updated_at` unchanged around a run). Default connection is the dev `mysql` one; it refuses any other host unless `--database` is given explicitly, and it prints which host it read.
**Tests (`tests/Feature/ProductIntegrityTest.php` + the scan):** a clean fixture passes; ONE corrupt fixture per invariant I1 to I5 (and W1, W2) names the offending id; the scan test; read-only proof; snapshot then compare equal; compare after one deleted line item shows exactly that difference. **Mutations (break, named test fails, restore byte for byte, `cmp`):** delete one registry row; disable I3; make I5 skip the offer name; make `--compare` ignore sums; make the command write one row.
