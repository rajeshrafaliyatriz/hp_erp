## What the first sweep showed, and what was done about it

- **P10 and P11 survived** (the organisation check inside `RecordNote` and `RecordTask`): the agent's own scoping hides these checks, so nothing exercised them. New `CrmRecordsTest` (11 tests) calls the two services directly with another organisation's record, a deleted one and one that never existed (the same not-found for all three), and covers text, dates, the duplicate guard and the calendar refusing.
- **P21 survived** (accept no longer re-reads the level of the action): the existing test switched the WHOLE agent off after a proposal was made; none switched off one kind of action. New tests in `AgentRunServiceTest` and `AgentGatewayApiTest` (accepting what has been switched off since is a 409 `policy_off`, nothing is written, and the person can still dismiss it).
- **P53 survived** (the `confirm_link` guard that one end of the pair must still be this organisation's): new `AgentRunServiceTest` test (the identity's CRM pointer moves after the proposal; accepting fails with the reason and the linker is never asked).
- **P55 to P62** were added after the first sweep for safeguards it had not covered (the cap on waiting proposals, the 500-character reason, the four presenter and panel lookups by organisation, the two tenant filters of the merge repoint). **P57 to P60 survived their first run**: those lookups carry the caller's organisation as a second line of defence (ids are unique across organisations, so no row of another organisation normally points at one of this one), and no test planted such a pointer. New `AgentGatewayTenantSweepTest::test_rows_of_another_organisation_that_point_into_this_ones_ids_show_nothing_of_themselves` plants all four (a decider of another organisation, a run pointing at another organisation's identity, another organisation's proposal re-pointed at this run and this identity) and proves nothing of theirs shows; P57 to P60 were run again and killed.
- **T08, T09, T19 and T22 were "killed" by a crash, not by a named test**: a failing `assert.equal(element, element)` makes Node print the whole jsdom object graph, and the test process ran out of memory (exit 134). The mutation WAS detected, but a real regression would have crashed the run instead of naming the test. Every assertion that compares DOM elements now uses `absent()` / `same()` (`lib/agent/assertions.ts`) and fails in words; T08, T09, T19 and T22 were run again and are killed by named tests.
- **T21 to T24** cover the behaviour added after the first sweep: the panel starts clean for another organisation, a late result for the organisation before is dropped, a refused accept reads the panel again, and the history screen says whose clock the days use.

## Not provable here

- `->lockForUpdate()` on the run start: sqlite has no row locks, so a mutation of it cannot be killed by a test; it was checked on the real MariaDB instead (`run-start-lock-dev-2026-11-03.md`).
- The `WHERE status = 'pending'` of the proposal claim is only reachable by a race: `AgentApplierClaimTest` makes the other request win between this one's read and its claim (P20).
