HOW IT WAS DONE (the runner and the mutant definitions are in ./mutation/)
- mutate.php: for each mutant it (1) checks the anchor text occurs exactly once, (2) writes the broken file, (3) lints it (a mutant that does not parse is INVALID, never a kill), (4) runs the named tests with --stop-on-failure, (5) if they all pass, runs ALL seven S10a test files before calling it a survivor, (6) puts the file back from memory and compares sha1 with the sha1 taken before the first mutation (the run stops if one file does not restore).
- Every run starts with a BASELINE of the whole S10a set that must be green, or nothing is mutated (the baselines read OK (175 tests, 1009 assertions) in pass 1 and OK (212 and then 214 tests) in pass 2).
- A guard refuses to mutate a file whose sha1 differs from the known-good manifest (added after a file lock made one restore fail, see INCIDENT).
- Scan mutants (batch 5) are never widened to the whole suite: the added Mail / Http / config lines are only ever READ by the static scan, never executed.

INCIDENT (fixed, no harm): during pass 1, batch 3, a restore of app/Domain/OutreachGate/Checks/SuppressionCheck.php failed with "Resource temporarily unavailable" (something else held the file for a moment). The runner detected it and stopped; the file was left with mutant SUP-02 in it for a few minutes (until I looked at the log). I restored it from the snapshot, proved all 47 files equal the snapshot (sha1sum -c) and added a retrying write, the known-good manifest guard and a stop-on-error chain. The batches that had already started afterwards aborted at their own baseline (a broken tree gives a red baseline), so nothing was mutated on top of the broken file. Every mutant of the interrupted batch was rerun.
