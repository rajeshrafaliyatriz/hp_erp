METHOD (the caller's rule: prove the baseline green first; break the code on purpose; a NAMED test must fail; restore byte for byte and cmp; mutate the GUARDS and the rights checks too, not only the happy path)
- Behaviour mutants (everything under app/): a scratch runner OUTSIDE the repository (never committed) writes the mutated copy of one or more classes (ProductWriter, CatalogueFields, ProductWriteAudit, ProductAccess, ProductMasterController) under its own folder and starts ONE phpunit process whose bootstrap `require`s the mutated copies BEFORE the autoloader can load the real files. The mutant is therefore the class the tests run against while the shared working tree is never written (other tracks were running tests in it at the same time, which is why). The runner hashes every file it mutates before and after the whole run; the md5 lines at the end of each batch say "identical", which is the cmp of a restore, trivially, because nothing was ever written. It runs with `--stop-on-defect`, so the first failing test is the one named.
- Baseline first: each batch runs every test file it uses with the runner's own bootstrap and NO mutant, and stops if anything is red (a command error would look like a 100% kill otherwise). It did stop once: my first parser read the pure "OK (n tests)" line as zero tests; fixed before any kill was believed.
- "Killed" = at least one named test failed. "Survived" = every test passed; each survivor is explained below, and the ones that were gaps in MY tests were fixed and re-run.
