## Findings while proving it (worth the caller's attention)

1. **A failing `assert.ok(expr)` with no message can run for minutes.** The first full mutation run never came back: one mutation made the late `assert.ok(notice(k).includes('Saved '))` of `export-screen.test.tsx` fail, and the test process then ran at 100% CPU for more than three minutes (verified: `assert.ok(false)` hung; the same line with a message argument, `assert.equal(1, 2, 'forced')` and a plain `throw` failed in milliseconds; the same kind of assertion earlier in the file failed at once). The cause is, I believe, Node building the message of a message-less `assert.ok` by re-reading the test file and parsing it token by token up to the call (inferred from Node's assert implementation, not measured). Every `assert.ok` in the files I added now has a message, and the runner kills a run after four minutes and reports it as a hang. **109 message-less `assert.ok` calls remain in the older Signals tests** (`company-opportunities-screen.test.tsx`, `signal-export.test.tsx`, `runs-panel.test.tsx`, `signal-generate-dialog.test.tsx`, `opportunity-query.test.ts`); a failing one late in a long file may hang instead of failing. I did not touch them.
2. **A test that clicks a missing button hangs.** `k.click(null)` inside React's `act()` leaves the act unfinished (the note on `pressButton` in `generate-fixtures.ts` says so). `pressLabel` in `screen-harness.ts` asserts the button first.
3. **One mutation was an equivalent mutant at the real numbers.** "No cap on the rows kept" (E3b) changed nothing at 2,000 rows, because 2,000 is a whole number of 50-row pages and the page-level stop already ends the reading. It survived the first run; a test with the cap inside a page (`cap: 75`) was added and kills it.
4. **One expectation of mine was wrong.** R7 (the window loses its title) was expected to be caught by the axe test; jsdom's axe does not see a missing dialog name. The mutation is caught by seven tests that read the title text; the runner's expectation was corrected and the first result is kept here.
5. **The export's Reason column is empty on both screens.** `GET /signals/opportunities` rows carry `review_notes` but no reason (`OpportunityController::presentMany` / `presentOpportunity`, read in source; `last_decision` appears nowhere in `app/` except the history presenter). `reasonLabel` reads `last_decision.reason_label` as the Review's export did. Filling the column is a backend change (list rows would need the latest decision's `reason_label` for dismissed signals), not mine.
6. **On the Generated source tab the list hides some rows on the client** (`signal-list.tsx:198`: imported rows have no run), while the server counts and the export returns them. The CSV, like the counts, holds the server's set for that tab.
7. **My first line-ending check was wrong.** Git Bash's `grep` drops the carriage return when it reads a file, so `grep -c $'\r'` said 0 for every file. Read with node, four of the files I edited are CRLF in the working tree (`advanced-tools.tsx`, `company-opportunities.tsx`, `use-generate-signals.ts`, `services/signals/opportunities.ts`; the repository stores LF and `core.autocrlf` converts at checkout) and the others are LF. My edits kept each file's own endings (`git diff` shows only my lines), and the mutation runner's first two multi-line search strings (G2, G3) failed to match a CRLF file until they were made single-line.
8. **The Review dialog's own test file is outside the mutation sets.** `signal-generate-dialog.test.tsx` is not part of them because of finding 1 (a failing message-less `assert.ok` in it hangs). The re-export that keeps that dialog working (`generate-model.ts`, `signal-run-service.ts`) is instead pinned by two fast tests (V1, V2 in the mutation table).
