# P1-C test map: every test of the deleted Signal Review code and where its behaviour is pinned now (13 Nov 2026)

Track S15-P1C, g2gv0 `milan1`, started from HEAD `cd6e20c`. Written BEFORE any deletion (and kept exact afterwards: the replacing tests were named here first and written to those names). Baseline 3,326 tests (3,324 pass, 2 known failures in `lib/expandable-run-notice.test.tsx`). The before/after account is at the end (section 5, filled in after the final run).

**Legend.** R = the behaviour is still pinned by a test that stays (named, with its file). N = no test stayed that pins it, so I WROTE one in a file that stays (named; each has a mutation proof in `p1c-mutations-2026-11-13.md`). M = the test is moved to the code that stays (same assertions, retargeted; also mutation-proved). D = the pinned code is deleted and the behaviour goes with it (reason given). X = the behaviour is NOT carried by the surviving code, so no passing replacement can exist (defect, section 4). Test names are quoted as they are in the source (where a name itself contains double quotes, the map writes those inner quotes as single quotes); deleted tests are shortened with "…".

Files of the replacing tests (all stay): `CO` = `lib/signals/company-opportunities-screen.test.tsx`; `HOOK` = `lib/use-generate-signals.behavior.test.tsx`; `PARTS` = `lib/signals/signal-parts.test.tsx` (new); `GC` = `lib/signals/generate-checks.test.tsx`; `RRS` = `lib/signals/run-research-service.test.ts`; `RF` = `lib/signals/run-failure.test.ts`; `SG` = `lib/signals-generate.test.ts`; `OQ` = `lib/signals/opportunity-query.test.ts`; `EXS` = `lib/signals/export-screen.test.tsx`; `RH` = `lib/signals/run-health.test.tsx`; `DD` = `lib/signals/decision-dialog.test.tsx`; `DA` = `lib/signals/decision-actions.test.ts`; `HL` = `lib/signals/history-list.test.tsx`; `LA` = `lib/signals/lead-action.test.ts`; `SD` = `lib/signals/signal-display.test.ts`; `PT` = `lib/scaffolds/page-tabs.test.ts`; `SPR` = `lib/sub-product-run.test.ts`; `SRN` = `lib/signal-run-notice.test.ts`; `RS` = `lib/research-steps.test.ts`; `LM` = `lib/signals/list-model.test.ts`.

## 4. Defects found while mapping (open, not fixed here)
**X1/X2: the surviving hook has no guard for an answer that arrives after the screen went away.** Evidence: `p1c-late-answer-experiment-2026-11-13.txt`. A question that was on its way when the screen went away is followed by another question (1 to 2); a start answered after the screen went away starts following (0 to 1 question). Cause: `components/domain/signals/use-generate-signals.ts` `follow` is guarded only by `generation` (changes with the product, not with unmount) and `started` calls `follow`. The dialog's tests 26 and 27 pinned the equivalent rule on the dialog's code. A passing test cannot exist without a product change (a `mounted` ref checked in `follow`, `finish` and `started`); not made here (this track deletes). The two cases that ARE carried (a late answer after the PRODUCT changed; the timer waiting when the screen goes away) are in HOOK.
